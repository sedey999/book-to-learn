# 踩坑清单（跨平台通用）

> 每条都是实战踩过的。格式：**现象 → 原因 → 做法**。
> 平台相关的案例会注明，但结论都按「跨平台」写。

## 一、渲染与字体

**1. 卡片被误判为「空白」并中断推送**
- 现象：产物明明有内容，校验却报 `image appears blank`，流程直接中止。
- 原因：校验只采样图片**开头若干像素**（如「前 1000 个像素」）。750px 宽的卡片在 dpi=150 下是 1172 像素/行，等于只看了第一行；卡片顶部恰好是白底就中招。
- 做法：**缩略后全图采样**（如 resize 到 40×40 再统计颜色数）。纯色图仍会被判空。

**2. 换一台机器就跑不动：PDF→PNG 依赖系统库**
- 现象：本机正常，换机器报 `pdf2image` 相关错误 / `poppler` 找不到。
- 原因：`pdf2image` 需要系统级 poppler（`pdftoppm`），pip 装不上。
- 做法：**首选 PyMuPDF**（`pip install pymupdf`，纯 wheel，无系统依赖），poppler 路径只作回退。注意新包名是 `pymupdf`，旧的 `fitz` 会打弃用告警，两个都要能识别。

**3. 中文破折号（——）在部分阅读器里显示为空白/方框**
- 现象：PDF 本地/桌面编辑器正常，某些阅读器或知识库预览里破折号消失。
- 原因：这些渲染器对 CJK CFF 字形里的 `U+2014 / U+2013` 兼容差。
- 做法：用 `@font-face` + `unicode-range: U+2014, U+2013`，把这两个码位单独交给一份 **TrueType** 字体渲染（DejaVu Sans / Arial 等，按平台探测），并把该 family 放在 `font-family` **首位**。

**4. 破折号兜底「静默失效」——字体家族列表过长（易忽略）**
- 现象：`@font-face` 明明注入了，破折号仍由 CJK 字体渲染，兜底没生效。
- 原因：实测 weasyprint 在**家族列表过长**时，逐字回退会整体退化为「全段用同一个字体」（14 个家族的跨平台列表会让整段落到 Noto Serif，`unicode-range` 的 `@font-face` 被完全忽略）；同样配置换成 3 个家族的短列表则完全正常。
- 做法：**`font-family` 保持简短（建议 ≤4 个家族）**，只列「本机探测到的真实字体」，不要堆砌全平台候选名。

**5. 判断 `@font-face` 是否已注入，不能只 grep 字体名**
- 现象：幂等判断写成 `if 'DashFix' in html: return`，结果注入被跳过、兜底失效。
- 原因：`font-family` 里也会出现同一个名字（比如由字体栈收敛步骤写入），于是误判为「已注入」。
- 做法：**匹配 `@font-face` 定义本身**（如 `@font-face[^}]*<family>`），而不是裸字体名。

**6. 正文里的 MDX/JSX 组件标签**
- 现象：卡片上出现 `<Step title="设置模式">` 这种噪声；或反过来，内容被 HTML 当成标签吞掉导致缺字。
- 原因：文档站（Mintlify / Docusaurus / MDX 类）正文混着组件标签，属性里的文字（`title=`）不在正文节点里。
- 做法：渲染前统一清理——带 `title/caption/label` 的开标签**提升为加粗引子**，其余标签剥离；`<img>` 交给图片映射。

**7. 卡片正面文字必须做 HTML 转义**
- 现象：`openclaw plugins install <plugin-spec>` 显示成 `openclaw plugins install`（尖括号内容消失）。
- 原因：文本被直接拼进 HTML，`<plugin-spec>` 被解析成标签。
- 做法：所有文本字段先 `html.escape`（转义 `< > &`），再做行内 markdown 渲染。

**8. 正文配图不显示，只显示 `<img …>` 文本**
- 现象：抓下来的截图在产物里整张丢失。
- 原因：渲染层没有把资源路径映射到本地文件。
- 做法：抓取时把图片落盘为**扁平化命名**（`/a/b/c.png` → `_a_b_c.png`），渲染时按「扁平名 → 相对路径 → basename」三种约定依次探测，命中后用本地绝对路径嵌入。

**9. markdown 表格不渲染**
- 现象：正文里的表格变成一堆 `|`。
- 做法：整块是表格时显式转成 HTML `<table>`（配边框/表头底色/斑马纹），单元格内容仍走行内渲染。

## 二、执行与流程

**10. 「改了却等于没改」——运行环境文件会回滚/易失**
- 现象：改完脚本、跑了一次，下一次发现改动没了（容器/沙箱被回滚）。
- 做法：**脚本修改 + 构建 + 校验放进同一条命令**一次完成，完成后立刻 grep/对比核对产物；关键中间产物每轮都验证，不依赖上一轮的记忆。

**11. 同一文件的多处编辑不要并行下发**
- 现象：两处改动只落地一处，随后报 `NameError`。
- 原因：并行编辑互相覆盖（后写的手里没有前一次的结果）。
- 做法：同一文件的编辑**串行**：改一处、拿到结果、再改下一处。

**12. 目标端没有删除能力时，重推会造成重名**
- 现象：某些知识库/平台没有删除接口，重新上传同名文件被自动加时间戳后缀，越堆越多。
- 做法：重推前先把旧文件**改名**成唯一前缀（如 `【旧版N-可删除】…`）腾出干净名，再上传新版；并明确告知用户需要手动清理哪些旧文件。

**13. 长文本写入被网关拦截**
- 现象：追加长内容（尤其含表格 `|` 或反斜杠）时请求被拦截（返回网关验证码页）。
- 做法：长内容走**对象存储上传 + 引用 key** 的路径，或拆小片、避开发力于转义的字符。

**14. 进度记录被污染**
- 现象：推送失败也记了进度，导致漏推。
- 做法：**只有成功才写进度**；失败必须发通知；重跑同一张不产生重复计数。

**15. 大批量推送的并发问题**
- 做法：**并行翻译 + 集中推送**。翻译可交给多个执行单元分工，但写进度/写笔记必须集中在一处串行，避免并发写坏状态。

## 三、内容质量

**16. 译文读起来别扭（翻译腔）**
- 做法：完整通读英文再动手；拆长句、少用被动与名词化；术语首次出现给「中文（English）」括注；**术语表与正文用词必须一致**；术语联网核对，不凭记忆。

**17. 编号体系混用**
- 做法：坚持**双轨**——文件名用「推送序号」（连续），卡片内标记与笔记录入用「清单绝对序号」（跳过会跳号）。

**18. 链接在目标端不可点击**
- 做法：正文里的 markdown 链接一律渲染为**纯文本**，完整 URL 统一列在「相关链接」区，方便复制。

## 四、拆卡（tile）实战补充

> 以下来自「把一份资料拆成一套竖版卡片长图」的实战。**关键几条已内嵌在
> `SKILL.md` 模式 C 与生成器产出的 `GUIDE.md` 里**，这里给出更完整的解释。

**19. 固定高度卡片「被裁剪但不报错」（拆卡的头号坑）**
- 现象：给卡片写死高度，内容超出后被直接裁掉，**weasyprint 可能不产生第 2 页**，靠页数检测抓不到。
- 做法：不要写死内容高度；改成「先渲染超长页**测量内容真实高度** → 超出则整体等比缩小字号（k）」
  的自适应；并把「页脚是否存在」作为必检项。`gen_card_tile.py` 已内置。

**20. 内容高度测量的阈值必须对照「页面底色」**
- 现象：用「接近纯白（>248）」判定内容区，会把浅灰页脚（≈247,249,251）漏掉，
  实测高度比真实内容矮一个页脚。
- 做法：以「与页面底色（#eaeef4 = 238,242,247）的差 > 6」判定内容区。

**21. 长标签把右侧图元挤出卡片右缘**
- 现象：flex 行里「标签 + 右侧图元」，标签不收缩时图元被挤出边界。
- 做法：标签用固定比例 `flex: 0 0 60%`；图元容器 `justify-content: flex-end`。
  注意 **weasyprint 下 `min-width: 0` 无效**（拿它做收缩保护不管用）。

**22. 空 `<span>` 画竖线/圆点不生效**
- 做法：用 `border-left`、或给元素显式 `width/height`；线状图元优先 `border`。

**23. flex 会把圆点拉伸成椭圆**
- 现象：着重号的圆点在 flex 行里被拉伸。
- 做法：`.gl-vdot { flex: 0 0 auto; width/height 固定; border-radius: 50% }`。

**24. 竖排/生僻字形：先确认字体能渲染，再上卡片**
- 现象：竖排引号（﹄﹃﹁﹂）、括号（︵︶）、竖破折号（︱）、浪线（︴︳）在缺字的字体下变方框。
- 做法：用一次 `glyphtest` 式的最小样张确认（Noto Sans CJK SC 可渲染上述字符）；
  不确定就退回「文字说明 + 几何标记」。

**25. 视觉模型会误判，也会自相矛盾**
- 现象：模型把全角字符/斜线/细竖线判成「裁切/缺失」，甚至一边说「底部被裁切」、
  一边说「页脚完整可见」。
- 做法：**像素优先**——以 `_check.json` 的 `ink_bbox` / `footer_ink_ratio` 等为判据；
  有疑问把局部裁开再看。听结论前先问「像素支持它吗」。

**26. 两处编辑同一 JSON 会互相覆盖**
- 做法：改内容统一写 `transform*.py`（幂等、可复跑），不要手改 JSON，也不要对同一文件并行下发多处编辑。

**27. 重排顺序后必须同步全部编号**
- 现象：调顺序后，卡片角标「第 X / N 张」、文件名前缀、文本稿序号只改了一部分。
- 做法：用脚本一次性重排 `index` 与 `total`，避免手改遗漏。

**28. 目标端无删除接口时，重推会堆重名**
- 做法：先把旧文件改名为 `【旧版N-可删除】…` 腾出干净名，再传新版；并明确告知用户要手动清理哪些。

**29. 「内容溢出」的校验本身可能假通过（最隐蔽的一条）**
- 现象：一张内容严重超量的卡生成了 **5 页** PDF，校验却报「通过、退出码 0」。
- 原因：校验用「底部区域有没有深色文字像素」判断页脚是否存在——溢出时被切到页 1 底部的
  正文文字同样带来深色像素，于是假通过。
- 做法：① 把 **PDF 页数 == 1** 作为硬判据（>1 即溢出）；
  ② 页脚判定改用**页脚底色带**：#f7f9fb 与卡片白底只差 8，颜色容差必须 **≤3**
  （≤10 会把白底算成页脚）；实测有页脚 ≈0.99、无页脚 0.00；
  ③ 生成时若 k 触到下限（0.62）仍溢出，打印 `[WARN]` 并让校验失败退出非 0——**宁可拦下，不要交付**。
